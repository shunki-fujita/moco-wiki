Development

開発・テスト・デプロイ

MOCO のテスト構成、リリースフロー、インストール方法。ツールは aqua で管理され、全コミットに DCO の Signed-off-by が必要です。

インストール

cert-manager が必須です（admission webhook 用証明書 + controller ↔ agent の gRPC mTLS 用 CA）。

# 方法 A: 生マニフェスト
kubectl apply -f https://github.com/cybozu-go/moco/releases/latest/download/moco.yaml

# 方法 B: Helm
helm repo add moco https://cybozu-go.github.io/moco/
helm install --create-namespace --namespace moco-system moco moco/moco

Helm の主要 values: replicaCount(2), crds.enabled(true, uninstall しても resource-policy: keep で CRD は残る), monitoring.enabled(PodMonitor ×3), agent.image.tag / fluentbit.image.tag / mysqldExporter.image.tag（サイドカーのイメージを差し替え可）, extraArgs。チャートは MOCO 本体と独立にバージョニングされます（chart 0.26.0 / app 0.36.0）。

テストの 4 層

層コマンド内容
単体make testMySQL/K8s 非依存。go test -race ./pkg/... + vet + gofmt
MySQL 依存make test-dbop / make test-bkopDocker で実 MySQL を立てて pkg/dbop・pkg/bkop を検証。MYSQL_VERSION で対象バージョン切替。bkop は mysqlsh が必要（make setup）
envtestmake envtestclustering / controllers / api (webhook) / backup の 4 サブターゲット。MOCO_CHECK_INTERVAL=100ms 等で高速化。FOCUS=... で ginkgo focus
E2Ecd e2e && make start && make testkind + cert-manager + MinIO / fake-gcs-server / Azurite。ginkgo --procs 5 --timeout 90m
cd e2e
make start                 # kind クラスタ + イメージビルド/ロード + MOCO デプロイ
make test                  # 本体 (RUN_E2E=1)
make test-upgrade          # 8.0.28 → 8.4 のアップグレードテスト (UPGRADE=1)
make start AGENT_DIR=path  # 未リリースの moco-agent を組み込んでテスト
make logs && make stop

E2E スイートは lifecycle / replication / failover / switchover / stop / offline / partition / pvc / prevent_delete / backup (S3, TLS, GCS, Azure) / upgrade をカバーしていますe2e/*_test.go。

コード生成

make manifests（CRD/RBAC/webhook → kustomize → Helm チャートの templates/generated/ まで再生成）、make generate（deepcopy）、make apidoc（docs/crd_*.md）。CI は make check-generate で生成物の差分をエラーにします。

リリースフロー

対象手順
MOCO 本体version.go と kustomization.yaml のバージョン更新 + CHANGELOG → PR → merge → v<X.Y.Z> タグ push でリリース CI 発火
Helm チャート本体と独立。Chart.yaml / values.yaml の tag を sed で更新 → chart-v<ver> タグ push
コンテナ (mysql / fluent-bit / mysqld_exporter)containers/<name>/<ver>/TAG を編集して main にマージするとリリース。TAG を変えないと Dockerfile を変えてもリリースされない。タグは <upstream 版>.<イメージ版>（例 8.4.8.1）
moco-agent別リポジトリでリリース → moco 側で go get github.com/cybozu-go/moco-agent@latest（--agent-image の既定値は go.mod から解決される）

サポートバージョン（CI マトリクス）

MySQL: 8.0.28 / 8.0.43 / 8.0.44 / 8.0.45 / 8.4.4 / 8.4.8（LTS のみ。Innovation release は未テスト）。Kubernetes: 1.33 / 1.34 / 1.35。k8s 1.35 では v1.35.4 以降か MaxUnavailableStatefulSet feature gate の無効化が必要（kubernetes#137409）.github/workflows/ci.yaml, README.md。

ソースと docs の食い違い（この wiki が見つけたもの）

ソースコードを正としてドキュメントと突き合わせた結果、以下の乖離があります。upstream への PR 候補です。

  • docs/customize-system-container.md: 「runAsUser=1000」と記載だが実装は 10000（pkg/constants/container.go）
  • docs/moco-controller.md: フラグ既定値のイメージバージョン表記が現行値（agent 0.16.0 / fluent-bit 5.0.2.1 / exporter 0.19.0.1）と不一致

  • docs/clustering.md: Offline 状態が未記載
  • spec.maxDelaySecondsForPodDeletion と prevent-delete アノテーション: 実装 + e2e はあるが docs に解説が無い
  • moco-agent の docs/moco-agent.md: 環境変数表に EXPORTER_PASSWORD / BACKUP_PASSWORD が欠落、--mysqld-localhost フラグが未記載、存在しない --logfile 等が記載
